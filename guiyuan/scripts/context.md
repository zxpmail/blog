# 归源现场 · 方案

C 是这一刻的事实。可以变。没写的轴就是空，不编。不可盖 [`charter.md`](./charter.md)，不可改 [`role.md`](./role.md) 的岗。不是宪章、岗位、性格、专家正文。

下面说的**这次对话** = 一次进模型的会话。对人一条，被委派另开一条，各装各的。

管此刻在哪、对着谁、目录里有谁、开没开编排、目标是什么。  
不管做完没、这一岗做什么、怎么说话、这个专家会什么。

**这次对话里必须一直在、忘了就坏的跟人段进 system。** 其余 C 不进。  
企业用户是谁、陪伴对着谁，真源按登录用户。标「关于他」。  
禁止写成「我是」「我必须」。用户要写成对自己的命令，写了也不算。

`AGENTS.md` 与 `CLAUDE.md` 只取 first-match 一种。说明书、黄页从真源投影。用户段键 `userId`。  
对人默认：用户段在 system，不灌黄页。  
开编排：说明书必须灌；必须卸用户段，用户要带着也不带。  
被委派必须灌说明书，必须有说明书，用户说不用看也不卸。不灌父对话、不灌用户段。  
跨用户房不搬 1:1 用户段，也不搬个人召回。卸了用户段仍搬召回，也算搬。  
甲的用户段不得进乙的对话，不得挂在 Agent 对象上。

本层装什么、卸什么，由装载器按入口表执行。用户要带着/套上/脱掉，也不改栈。

任务单走子 user 属本层（C）；单子怎么写才自洽，写法见 D。目标当数据，不另定完成标准。

目标提示词（进模型的事实稿）按入口拆开：[`C-user.md`](./C/C-user.md) · [`C-default.md`](./C/C-default.md) · [`C-orchestration.md`](./C/C-orchestration.md) · [`C-worker.md`](./C/C-worker.md) · [`C-group.md`](./C/C-group.md) · [`C-projection.md`](./C/C-projection.md)。装卸总表见 [`loader.md`](./loader.md)（仓内切法 LOADER-DRAFT）。
