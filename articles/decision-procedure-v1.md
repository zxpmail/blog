# 判定程序　最小子集、声明封口与重放

版本 1。本程序与讨论篇的规则一致。讨论篇没有模板的地方，以这里为准。

登记时间由接收系统在提交时分配，调用方不能指定。单库用自增序列，或该库上单调递增的时间戳。不需要分布式时钟。多个库各自分配再放在一起比先后，不在这三档里。`derived-from` 的父记录必须已经提交，因此子记录的登记时间晚于父记录。锁不设「后代早于祖先」：在这条不变量下它走不到。导入若要保留外部时钟，写入发生时间或来源时间，不写入登记时间。

## 一、三档

| 档 | 实施内容 | 维护面 | 不能声称的结论 |
|---|---|---|---|
| 最小档 | 端点；`part-of` 拒环；种类只有组分；事件追加不改写；系统分配登记时间并按它截断；直接计数（仅 `instance-of`）；全库一个锚点，情境边不带限定符 | 一个模块里的常数条检查；查询随边数 | 更正之后的部分结构；第二张工单的末端；补偿链；含子类型计数 |
| 第二档 | 最小档的全部，加上更正载荷、先截断再施锁、各轨道同一个截至时刻。单锚点时限定符可带可不带。出现第二个锚点时必须带限定符，多锚点的当前情境查询可用 | 多一块按事实键比较的代码；顺序由第五节用例核对（15:40 期望否，16:10 期望是） | 多种类；补偿链；含子类型计数；「符合本文判定程序（版本 1）」 |
| 全文 | 第二档的全部，加上种类注册与两条默认配对规则、三种声明且无第四种、补偿链与当前情境分开查询、过滤仅 `inheres-in`。含子类型计数在计数声明内，不另成一项 | 发版与评审。查询仍随边数，不启动推理机 | 「全文另加」任一项未勾选时，不得使用「符合本文判定程序（版本 1）」 |

从最小档到第二档，增加的是更正、截断顺序和多锚点查询。从第二档到全文，增加的是种类、补偿链和声明封口，锚点不必重做。不允许「第二档再私加一种声明」：要计数声明或补偿链，就升到全文。

查询「有没有一条合法路径」在三档都随边数结束。把全部路径列出，或把传递结果整张物化，才按输出规模变贵。这是查询成本。上表是规则的维护成本。

## 二、关系、种类与写入

| 关系 | 组别 | 规范方向 | 端点 |
|---|---|---|---|
| `part-of` | 血缘·结构 | 部分 → 整体 | 同侧。种类 ∈ 该版本注册表 |
| `triggers` | 血缘·情境 | 情境 → 事件 | 第二档：单锚点时可带可不带限定符；多锚点时必须带 |
| `brings-about` | 血缘·情境 | 事件 → 情境 | 同上 |
| `derived-from` | 血缘·记录 | 记录 → 直接父记录 | 记录 → 记录。第二档起 |
| `compensates` | 锚定 | 补偿事件 → 被补偿事件 | 事件 → 事件。全文才使用 |
| `participates-in` | 准入 | 对象 → 发生 | 持续体个体 → 事件或过程 |
| `realizes` | 准入 | 事件 → 倾向 | 全文的实现问句才使用 |
| `instance-of` | 准入 | 个体 → 类型 | 最小档起，只用于直接计数 |
| `is-a` | 类型 | 子类型 → 父类型 | 全文的计数声明才使用 |
| `inheres-in` | 依存 | 倾向 → 承载对象 | 只作过滤，不作枢纽。全文才使用 |

角色和锚点都是限定符，不新增关系名。最小档不使用 `realizes`、`inheres-in`、`is-a`、`compensates`、`derived-from`。

对象与倾向在对象侧，事件与过程在发生侧。`part-of` 的一步必须同侧。两步可接，还要共享枢纽、种类相同。

版本 1 的注册表只有组分、时段切片。未注册的种类写入拒绝。配对不逐对手写，由两条规则生成：同种类可接；不同种类停止。某对不同种类要放行，必须在该版本里逐对写成例外。没有例外的跨种类对就是停止。新增种类只能发下一版，默认仍是这两条规则，再加该版写明的例外。最小档和第二档的注册表里只有组分，不启用时段切片。

`part-of`、情境边、`compensates` 都在写入时拒绝有向环。情境上的往复用新节点展开，类型名可以相同。读取时若仍看到环，只说明检查被绕过，或迁入了未拒环的旧数据。该次查询返回「有环」，不给末端，也不把环当成合法循环。补偿链上的环适用同一句，不是业务上可以产生的循环。

`brings-about` 的起点必须是事件。过程终点为空时不能做起点。完成后把参与按同一角色再写到事件上，过程上的边保留。

## 三、时间、截断与锁

发生时间回答事件何时发生。登记时间回答边何时进入边集，由本系统在父记录已经提交之后分配。「截至 T」包含登记时间 ≤ T 的记录，T 本身算在内。

重放只截断一次，结构、情境、记录轨道共用这个 T。顺序是：先截断，再在留下的记录上施锁，然后做轨道、衔接、过滤和末端。先施锁再截断时，T 之后的更正会先改变胜者，随后被丢掉也不会把胜者改回去。

当前情境查询所用的边集，写成「截至 T，先截断再施锁之后的生效边」。

事实键是 `(关系名, 起点, 终点)`，改属性时再加属性名。候选只包括对该键写了显式加入或显式撤回的记录。原记录里有这条边，算加入。原记录没写，是未提及，不算撤回，不入候选。没有候选，生效边集里就没有这条边。

- 若 A 是 B 的祖先，则 B 胜过 A。父记录先提交，这一支不再比较登记时间的早晚。
- 若两条互不为祖先，登记时间晚者胜过早者。
- 同一事实键上登记时间相同，该键返回「冲突」，不另设批次号去打破。系统应尽量分配出不同时间；做不到就拒绝给出胜者。不同事实键上的相同登记时间不是冲突。
- 唯一胜者是加入，边生效。唯一胜者是撤回，边不生效，其上属性一并无效。

迁移优先用一条记录携带多个事实键。若一条记录只能带一个键，就写两条，共用同一登记时间，并用事务保证要么都提交要么都不提交。旧键上只有撤回，新键上只有加入，锁不在这两个键之间选择。截断时，T 要么留下两条，要么一条都不留。事务失败不在锁里补救。

外部标识只存稳定键。展示名称改变而键不变，端点不变。换键走上一节的迁移，未迁移前路径仍指向旧键。

## 四、声明封口

本版声明只有三种：换轨、计数、补偿链。一种衔接合法，当且仅当它出现在下面的规则 A、换轨的两步、计数声明的唯一步骤，或补偿链对 `compensates` 的行走中。其余复合拒绝。新的声明类型或新的过滤谓词只能随下一版本发布，并在该版写明与这三种互不混用。计数声明和补偿链属于全文。最小档和第二档不解析它们；收到这类声明，拒绝并说明档位不够。直接计数不是计数声明，最小档用 `instance-of` 的逆即可。

规则 A 只产生候选，不写入边集。`realizes` 那两行属于全文。最小档和第二档只使用第三行（同一次发生上的共同参与）。

| 模式 | 枢纽 | 候选 |
|---|---|---|
| `participates-in` 然后 `realizes` | 事件 | 经由哪些事件实现过哪些倾向 |
| `realizes` 的逆，再 `participates-in` 的逆 | 事件 | 该事件上有哪些对象 |
| 两个 `participates-in` 对读 | 事件 | 谁与谁共参与。不产生对象之间的边 |

规则 B：准入再走血缘，必须换轨。不产生「此人带来了该情境」。规则 C：不能省掉枢纽。

换轨最多两步。枢纽不点名则拒绝。枢纽可以是一个节点，或一个集合；集合只取并集，再沿第二步扩展。不提供交集。需要交集时拆成两次查询，由人点名中间结果。

过滤可选，且只有一行，放在声明最后，仅全文使用。这一行只允许 `inheres-in`：候选倾向依存于问句里的那个对象。不允许布尔组合、嵌套或其他关系。没有这行时，候选可以包括依存于别人的倾向。过滤在全部候选得出之后做一次，不插在每一步 `realizes` 后面。

```
问句：
有效边集：版本 1，截至 T（先截断再施锁）
1. 组别与关系：从 ____ 到枢纽 ____
换轨：枢纽 = ____（节点或并集）
2. 组别与关系：从枢纽到 ____
过滤（可无，仅全文）：候选 inheres-in ____
写入新边：否
```

计数不走换轨。它是本版唯一允许写在规则 A 之外的衔接，步骤不能改。仅全文。含子类型与直接计数是这一声明里的两个选项，不是清单上的另一项。

```
问句：
计数：直接 | 含子类型
类型：____
有效边集：版本 1，截至 T（先截断再施锁）
步骤：若为含子类型，沿 is-a 的逆收集子类型（含被问类型），再取 instance-of 的逆
     若为直接，只取 instance-of 的逆
写入新边：否
```

补偿链不与情境边拼接。效果另做一次当前情境查询。仅全文。

```
问句：
起点：____（事件）
方向：顺（沿箭头，补偿事件 → 被补偿事件）| 逆（逆箭头）
步数：一步 | 沿链
有效边集：版本 1，截至 T（先截断再施锁）
写入新边：否
```

顺箭头回答「它补偿了谁」，逆箭头回答「谁补偿了它」。默认问句只走一步。沿链在无环图上会停。读取时若仍有环，与第二节相同：只说明写入检查被绕过或迁入了旧数据，返回「有环」，不是合法业务。直接补偿边不因后来又有补偿而删除。效果是否恢复，只看当前情境的末端类型。

```
问句：工单 WO-1 的当前情境
有效边集：版本 1，截至 T（先截断再施锁）
1. participates-in 的逆：从 WO-1 到枢纽集合
换轨：枢纽 = 该集合的并集
2. 只走限定符为该工单的情境边，取无向连通
   有环 → 「有环」
   否则收集不再发出 triggers 的情境节点
写入新边：否
```

不声明锚点，结果是「未指定轨道」。集合不是一个元素，结果是「多末端」，不代选。最小档只有一个锚点，限定符不写，第二条链拒绝写入，因此不回答第二张工单的末端。第二档在单锚点时，限定符可带可不带，两种都不违规。出现第二个锚点则必须带，连通只沿同一限定符走，各锚点的当前情境查询可用。

## 五、走查中的判定实例

版本 1。最小档和第二档的种类只用组分。全文才启用时段切片这个名字，本例没有用到它。本例发生时间与登记时间相同。CL-1 于 12:10 登记，截至 12:10 包含它。若改到 12:11 才登记，截至 12:10 的末端仍是 S4。

全文才做这一问。AS-12 实现过哪些倾向：第一步从 AS-12 到枢纽 OV-1，第二步 `realizes` 得到 D-hot，过滤 `D-hot inheres-in AS-12`。答案是 D-hot。过滤不是第三步衔接。

以下到 16:10 为止是第二档核对。

更正：CR-1（15:00）加入「RT-1 是 FIX-9 的部分」。CR-3（15:30）撤回同一键，与 CR-1 互不为祖先。CR-2（16:10）指向 CR-1，再次加入。原记录没有这条边，不是撤回候选。

先施锁再截断得到「是」，该实现不能勾第二档。

以下属于全文，第二档到此为止。

## 六、事件溯源的接入点

扩展点在消息类型。更正消息写成父记录加上事实键的加入或撤回。补偿消息写成新事件，外加一条 `compensates` 和情境轨道上的新节点。格式不能拆时，在接入层做映射表。映射表属于采用本程序的实现。消息不拆，锁和补偿锚点都无法执行。补偿消息属于全文；只做到第二档的系统拒绝这类消息，而不是把它写成更正。

## 七、符合性清单

先选定一个档位，再勾该档以及它包含的较低档，最后只用该档对应的一句。有锚点、没有补偿链，使用第二句，不使用第三句。只做了锁、却先施锁再截断，不能勾第二档，也不能使用后两句。

```
版本：1
本实现的档位：最小档 / 第二档 / 全文（只选一个）
最小档：端点 __  拒环 __  登记时间由系统分配（自增序列或单库单调时间戳） __
        按登记时间截断 __  直接计数（仅 instance-of） __  单锚点且不带限定符 __
第二档另加：更正锁 __
            先截断再施锁（15:40 期望否；16:10 期望是） __
            各轨道同一截至时刻 __
            单锚点时限定符可带可不带；多锚点时必须带，且可查询各工单当前情境 __
全文另加：种类默认规则 __  三种声明且无第四种（计数声明含「含子类型」，不另勾） __
          补偿链与当前情境分开查询 __  过滤仅 inheres-in __
未实现的项目不得出现在对外结论中。
可使用的句子只有下面三句原文，版本号已在句内，不要另加或删掉：
「实现本文最小子集（版本 1）」
「实现本文第二档（版本 1）」
「符合本文判定程序（版本 1）」（仅全文且「全文另加」各项都勾选）
```
