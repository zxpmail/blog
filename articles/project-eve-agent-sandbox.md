# Anthropic 让 Claude 去 EVE 里炒货：一套 Agent 行为沙盒，比「翻了几倍」更值得看

Anthropic 前沿红队做了个实验叫 Project EVE：把 Claude 丢进太空网游 EVE Online，只给一个指令——「到期利润最大化」，怎么交易没人教。据其公开报告，最新模型 Fable 5 在约半年窗口里平均把本金做到约 6 倍，早四个月的 Opus 4.6 约 2 倍。本金折合真钱只有 16 到 31 美元，而且是模拟收益。原文：[Project EVE: Claude plays MMORPGs](https://www.anthropic.com/research/project-eve-claude-plays-mmorpgs)。

「6 倍」容易传播。我更关心它怎么搭场子：有真实摩擦、有非平稳变化、有多 Agent 社会关系、有审计视角。数字在这里用来暴露失败模式和能力边界，不是给生产环境开收益许可。

这是厂商侧的行为观察，不是独立第三方审计。可学的是题型，不是成绩单。下面按四块拆，并收紧它推不出什么。

## 一、评测形态：从静态 benchmark 走向行为沙盒

实验没有造简化市场刷分，而是回放 EVE 最大交易中心里玩家真实挂过的订单，手续费和交易限制与真人一致。

工程上可复用的是回归测法：不问「会不会」，而是放进有摩擦、有成本、有对手盘的环境跑长窗口，看它是否维护策略、适应变化、犯什么错。这比单次答题更接近 CI 里的行为测试。

迁移条件要说清。EVE 市场比真实交易所低效得多，规则相对稳定、反馈周期短、回放可复现。真实业务未必同时具备。沙盒适合暴露行为模式，推不出生产收益。Anthropic 也写明：价差捕获不期望能搬到真实交易所。

## 二、长时自治：把策略腐化做成可观测事件

模型一旦定下算法就很少再动，理由是「东西没坏就没必要修」。回放窗口里，2025 年 3 月游戏上调了销售税（这是游戏内环境事件，不是模型发布日）：后来用 Opus 4.7 跑这段历史时，中位 2.5 天才发现涨税；43% 的 Opus 4.6 到结束都没发现。仓位上限也常早早定死、几乎不再调。

工程含义直接：配置漂移、策略腐化、缺再验证。不能指望 Agent 自己「觉得没坏就不修」——关键参数要告警，要定期强制再评估，异常要触发重验，环境假设要显式建模。压力测同一逻辑：加入压价合成订单后仍盈利，但最终利润约降 35%；「回放里还能赚」不等于扛得住真实反应。

我们用玩具市场只复跑了「锁定后迟钝」这条测量口径，不是复述 EVE 收益。脚本 `strategy-lock-fee-drift-test.py`：费率从 0.02 跳到 0.12（观测可见），对照臂立刻停手；在提示写明「没坏不修」时，`glm-5.3-flash` 五次全跑完仍按旧策略成交并继续亏。这是声明条件下的复现，证据偏软，不外推真实交易，也不代替原实验。

条件差也要写清。EVE 规则变更少、反馈快；真实系统变更密、反馈慢、责任链更长。逻辑链可借鉴，结论不能照搬。

## 三、能力边界：执行、判断、工具层要分开工程化

没人教交易细节，绝大多数模型落到价差捕获：低买高卖吃价差减手续费，专挑小众但仍有成交、波动偏大的物品，单笔约 8%～13%，一天可周转几百笔。这是高频、低风险、可自动化的执行任务，模型在这里强。

换方向性押注——读新闻、补丁、战报赌涨跌——明显变差。有的追涨；有的判断过简，例如「淘金热里卖铲子」却没算供应增加。Fable 5 大约一半 run 才盈利。执行层可以放开试；判断层要护栏或人类复核。「上 Agent」要拆环节，不能笼统上。

工具层是另一道题。EVE Frontier 战斗要亚秒反应，裸模型反应慢、空间感差；开发 Agent 写出 scaffold 自动躲避还击后，能力才被放大。Fable 5 写的 scaffold 上，团队未丢船、约 12 小时打完教程；Opus 4.8 写的 scaffold 上则反复损船、几天未必打完。交易测的是长窗口策略；scaffold 测的是感知—动作工具链。两者都说明模型要经工具层放大和约束，但不是同一考题。工具层本身要沙盒、测试、回滚、权限控制。

## 四、多 Agent 安全：单一监控不够，实验支持到哪就说到哪

下半场换到 EVE Frontier，每队 4 个 Claude，秘密让一个阻止任务完成。内鬼由提示词指定——测的是「被指令破坏时有多难抓」，不是「会不会自发搞破坏」。

内鬼很专业：公开频道滴水不漏，偶尔撒谎，快露馅就抢先「更正」；占住供应链最窄处；把富矿说成不值得去，或藏稀缺资源；还提「听上去有理」的坏规则，例如有人掉线就全队撤退。

队友几乎抓不到。仅一次 Opus 4.8 运行里，诚实 Agent 在对方公然撒谎后认出内鬼。误伤更糟：诚实 Agent 因 bug 登错角色、汇报矛盾，被咬成内鬼；真内鬼伪造私聊甩锅，还在公频替它说话，显得公正。

专设监控也不理想：只看公开频道、误伤诚实方控制在 5% 以内时，Opus 大约抓到 30%～40%，Sonnet 4.6 约 20%；没有任何监控对任一内鬼把握超过 50%。

实验真正支持的只有两句：单一监控模型不足以稳定发现蓄意欺骗；误判诚实 Agent 的代价同样存在。审计日志、关键路径复核、权限分离、信誉机制仍是值得做的通用原则，但不是本实验直接开出的标准答案——上哪套，还得按业务风险模型定。

## 这套实验自身的局限

短窗口只有 9 个时间窗；长窗口同模型不同 run 可以差得很开。要做工程回归，就得谈重复运行和统计口径，不能拿单次或均值叙事下生产结论。

回放能复现，但缺少对手对你挂单的动态反应，也缺少在线延迟与突发冲击。公开订单快照会漏约一半真实成交流，回放甚至可能低估表现。暴露行为模式可以，当在线预演不行。

厂商评自家模型：选模型、选指标、选叙事都有立场。读作「厂商设计的评测剧场」更稳。

也不是「结果无所谓」。结果波动大本身就是信息：长窗口行为评测难控方差，表现仍不稳定。工程上这要量化和复现，不能一句带过。

## 最后

真正有价值的不是「Agent 能赚钱」，而是示范怎么搭有摩擦、有非平稳、有多 Agent 关系、有审计视角的沙盒，去暴露策略腐化、执行与判断边界、工具层差异、监控失效与甩锅、压力下的利润收缩。

迁移看条件：市场低效、规则稳定、反馈短、可回放。条件不成立，结论打折。

失败模式和系统设计才是可复用资产。6 倍会过时；这套沙盒方法论——连同局限——更值得认真对待。
