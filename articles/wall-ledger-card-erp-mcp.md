# 墙、账、卡：把一个会编数据的模型接进生产 ERP

测试记录里躺着一句很有底气的话：「查询到了2个会计科目」。

说这话的是我们的大模型。那一轮它一个工具都没调用成——agent 平台的白名单机制静默失效，工具根本没到它手上。它没有报错，没有卡住，而是若无其事地编了一个答案，附上两个科目，语气笃定，像刚刚查完一样。

库面那一天的调用记录是零。

这是给企业系统接 AI 助手绕不开的一幕：**至少在我们手里这个模型上，它不会在缺工具的时候停下来，它会编一个答案继续走。** 换更贵的模型、加重试、加提示词——会不会好我们没验证，也不敢赌。这一类风险大概率不会被「更聪明」消灭：根源不在智力，在话面天生要把话说圆。

所以真正要解决的，从来不是「怎么让模型答对」，而是：

**怎么造一个系统，让一个会编数据的模型在 MCP 主路、我们枚举出的攻击面上伤不到库——并且这件事可以机械地验证，边界也说得清楚。**

会话被冒充、文件导入、定时任务，不在这句承诺里。答案塌缩成三个字：墙、账、卡。

这不是教程，是战地笔记。联调窗口三天：单文件 MCP 网关、一个便宜小模型、开源制造 ERP。卡册、墙的前几版、agent 平台都早于这三天；三天是接到生产路径上、把纪律写死的窗口，不是从零发明的工期。

## 一、局面

底座是 ERPNext v16，剔除坏面后约 500 个业务对象（doctype）。上层自研 agent 平台，走 MCP 挂工具——每个 agent 靠一份「门牌」（agent→工具面的映射）知道自己能用哪一面。模型是 GLM 最便宜一档——刻意的：只在贵模型上成立的，不叫架构，叫烧钱。

用户说「建个客户叫张三」，助手回两行：

```
新建客户「张三」，类型：企业。
1 确认 / 2 取消
```

回「1」，库里多一行。创建人不是助手账号——助手纯只读；真写换成执行账号，且只在确认走完后出手。审计账仍记助手这条编排链：谁放的行、谁建的行，两本账。回「2」，什么都没有。这一刀是 §4 直连洞逼出来的。

在 **MCP 主路、枚举出的实体和方法键** 上：诱导、模型自己补确认词，都不该让不该写的数据落库。旁路和会话层见文末。

验证两本考卷，任务不同，不打架：

| 考卷 | 考什么 | 绿认什么 |
|---|---|---|
| 普查 | 册上对象／方法键逐笔打过 MCP（一个对象或一个方法键＝一「腿」：腿即一条测试用例） | 审计账（话面糊、账齐的按账收口，不重试翻案） |
| 剧本 | 写死的短对话：话面钉死字 + 库面有行 | 话面与库面一起过 |

剧本里回 1 后若未见「已创建／已取消」，执行器再回一次 1——回的是确认话面，不是写请求，一次性凭据兜底，与下文禁盲重试不冲突。条数见文末；这里只记：普查不证明模型会说话，剧本全绿不证明五百个对象话面都准。

## 二、账：话面靠不住，只认账

话面撒谎，而且从容。除开场那句假科目，还有两种：

**幻影回执。** 模型声称「已收到确认」，实际什么都没收到。测试机器人若信了去重试，会把同一笔写发第二遍；写凭据一次性，第二遍烧掉凭据，真写反而失败。定死：**机器人只认审计行出手，禁盲重试**；「已收到」「已点批」一概不接茬。

**双发残行。** 同一回合工具调用发两遍：先残缺被拒，再正常通过。账面两条。消费者改成「末条成功行胜」——末行若是拒绝，不算胜。

三层各记各的：

| 层 | 记什么 |
|---|---|
| 审计账 | 网关裁决——放行、拒绝、要确认、写落库，一行一条，带原因码 |
| 线界转储 | 模型发出的参数原文 |
| 库面 | 真实的行和创建人 |

端到端红了：先审计，再转储，最后定性。有一次套件 19/20，人工六步重放（不走模型，请求亲手过墙）证明墙链无缺，红在模型重发丢了参数字面量。纪律：**墙对、模型不合规 → 模型抖动，不是产品缺陷。** 配反向扳机：**同一形态的红重复出现，回头疑墙。** 抖动随机；有规律的红是墙或协议在确定条件下错了。「模型抖动」不能当永久挡箭牌。

两条小而硬的：

- **过墙 ≠ 落库。** 各写各的账；审计有独立 WRITE 行之后，绿色才分得清。
- **对账先对准账本。** 分域后各网关各写各的审计文件；拿错账本，绿也是假绿。

还有一条常被忽略：**库面断言分不清是谁拒的。** 底座权限拒绝和墙拒绝，在库里长得一样。多角色共库时，「返回 200」什么都证明不了。断言必须断到层：落到哪个角色的审计账、创建人是不是该域执行账号。不断层，等于没断。

## 三、卡：语义是数据，不是代码

模型要跟约 500 个对象打交道，得有人告诉它对象是什么、字段、必填。这就是语义卡。

领域研究收卡，剔坏、并卡、补录后定稿在册；坏面另册。后来长成六件套：剔除名单、中文概念句、别名表、域划分、子表快照、运行时合并册。只认一句：

**语义是数据，不是代码。** 加实体、改域、剔坏面、补概念——改数据文件加重启，网关代码不动。

四个坑逼出这句话。

**坏面残留。** 一批 doctype 在站点元数据里有、库里没有表——上游废弃残留。一碰就 HTTP 500 报错，桌面／API／AI 一起炸。不写代码拦截，用剔除名单：启动时从卡册摘掉，权限影子同步删；上游修好就摘名单重启。子串匹配差点误伤：名单有「Bank Clearance」，库里还有真子表「Bank Clearance Detail」。

**通配符吞配置。** 域划分文件落地当晚，启动逻辑按 `卡-*.json` 合并，把纯配置当实体卡吞进去，实例集体崩溃。规矩：**新数据文件进场前，先问通配符认不认我。**

**忘了重启。** 数据启动时载入。「改了怎么没生效」，九成是没重启。

**手抄契约腐烂。** 各域 skill（给 agent 的操作说明书）里的高频契约摘要，第一版人手抄。卡册一迭代，手抄无声烂掉。改成从卡册生成视图，`--check` 零漂移，手抄禁绝。**权威唯一在卡册；两处权威等于没有权威。**

`--check` 只锁**内部**派生对卡册。锁不住**上游**：ERPNext 升级后字段、废弃、坏面名单会一起无声烂。上游漂移检测未做，登记在案——联调接得上卡册，谁长期养卡册，没有答案。

## 四、墙：每一版少信一点模型

墙是网关守门人，模型对 ERP 的请求都从它过。管四件事：请求形状、场景白名单、写确认、预算熔断。哲学一句：

**每一版都比上一版少信一点模型。**

管辖边界先说死。形状、白名单、预算，读也过——册外对象读不出去；助手又纯只读。确认只挂在写上。**不管**读完之后的转述，不管转述里有没有夹带物料名、备注里的存储型内容。白名单内读过多、敏感字段被套出、库字符串反过来指挥模型——空白，见文末。

**第一版两段式。** 写先登记拿一次性凭据 → 转述用户 → 用户同意后带凭据重发 → 墙核摘要放行。拦得住坏模型，拦不住「守序的笨」：没有用户同意，模型也能自己补确认词。测试里白纸黑字重现过。

**第二版三段式。** 写许可搬出 LLM 通道：对话内确认之外，ERP 里还要有一张在册单据被真人点过批。登记永远是助手账号；「已批」状态转移（口语叫翻面）只许非本人会话——助手自批自会被底座 417 拒绝，墙都不用出手。**坏心无兑换力。**

**第三版退回单因子。** 动因是用户一句「怎么看不懂呢」。带外点批要登录找单；确认改成「非空即可」，话面两行「1 确认 / 2 取消」，回 1 即写。防伪靠：凭据单次、十分钟内有效（上限）、「已拒」一票否决；另加**驻留**——确认快于最短间隔也拒（下限），防模型秒回。两块表不要并成「驻留十分钟」；剧本里睡五秒踩的是下限。

单据留下只作台账，加「已拒」否决，不再要求人去系统点。这防的是模型伪造同意，**防不住通道被冒充**：劫持者回 1 与真用户回 1，墙眼里一样；渲染被污染显示成「1 确认」，墙也分不出。价码标在账上：会话层联调窗口未加固。

四条铁律，各跟一个故事。

**权限即墙。** 助手账号绕过网关直连 REST：建、改全 200——确认钩子只挂在 MCP 上。不是加脚本堵，是助手收成纯只读，写走独立执行账号，没配就拒。**墙的定义域必须在权限层；钩子只护看得见的门。** 洞是试出来的，可能还有没试到的门。

**门禁与模型同规。** 销售订单链一度六轮零通过。模型确认时把子表数组打成字符串——不是篡改，是记不成数组。登记数组、确认字符串，摘要报红；模型更努力传字符串，类型死锁。修法：两侧都先把字符串子表还原成数组再算摘要。**编码歧义不算漂移，真改值仍拒。** 协议吸收外设的不可靠，不惩罚它。

**回执是外存。** 确认回执回显完整载荷，让模型照抄。要求「原样重发」危险——模型会回到自己上一轮草稿。凡要转述的，话面内嵌全字面量。

**翻面失败要出声。** 控制器曾只许「已批→已执行」，回 1 走的是「待批→已执行」，417 静默吞掉——库写入成功，单据永悬待批。修控制器，并加「翻面失败」审计行。**静默失败比失败贵。**

## 五、四则最贵的静默失败

拆合做了三轮（角色与业务面、skill 与门牌、凭据号）。真正贵的是「有一层在说谎、其余层还在报绿」。四则里，**静默吃到旧墙**和**同名工具面顶成最后一角**是同一族毛病：测试绿了，世界换了。

**凭据战争。** 通用域测试连红。先疑模型供方，半轮无获。把配置里每把凭据单独打库：401。墙审计仍放行（查白名单，不查底座票），话面一句含混「认证错误」。**三层里只有一层说真话；不逐层验就归因，必然归错。**

助手账号一把钥匙多家共用：谁重签，谁生效，别家票作废。我们重签修好自己，打死另一条线刚同步的票；对方写「密钥被带外轮换，非本仓库行为」——说的就是我们。纪律：**再遇 401，先试别处配置里的票，不要直接重签。** 普查拆了独立用户、复用角色权限影子；通用助手与共用环境（口语叫笼号）共钥仍未根治。

**静默吃到旧墙。** 研究目录默认指主检出。多检出新实例起来后，静默吃到主检出旧墙——新提示词配旧墙行为，测试全绿，写口径却错。异检出必须显式点名配置。**静默错配比报错贵一个数量级。**

**同名工具面顶成最后一角。** 通用面先立，后来拆出六业务面，每个面按域重注册一遍。注册名是全局单点，最后注册的赢——于是每跑一条腿，通用面就被顶成那一角的域面。跑完，测试全绿，但「std 注册」实际指向的是另一个域。没有报错，没有冲突提示，只有一块门牌被静默改写。修法是独立面、PRE 阶段钉住 std、跑完自动还原。**这族毛病的共性：不是墙破了，是门牌换了；而账上的绿，还没来得及知道世界换了。**

**测试删了真实客户。** 清场一度按名字删，删到用户当天下午新建的客户。他问「创建成功但查不到」，两小时三个人两个答案，其中一个是我们的测试。改成快照差集：开跑记名字集合，结束只删本轮新增。**幂等测试，删除数应当是零。**

同族还有一记：门牌没钉牢时，模型会调别家的面——墙都没破，绿也解释不了「世界已换」。skill 许诺墙不认的对象、并行前不搜台账号、续跑对账器起跑读全历史——另册登记，此处不展开。

## 六、驯模型与剧本库

样本：一个最便宜档 GLM、三天联调、有限轮次。田野观察，不是定律；当下界：最不听话的外设圈得住，更乖的大概率也圈得住。

硬钉：工具参数必须是对象字面量（字符串会静默变空对象）；一回合一次调用；空列表是真回执，不是失败。

复现过的退化：确认时改口重新登记（换新凭据）；数组打成字符串；脑补「去 Desk 点已批」；自编「ITEM-0001」走捷径；「1 确认」写成「1. 确认」。约十个回合有健康窗口；依从度跨夜波动，归因未分清。

总纲：**模型是不可靠外设。** 缺省必问、不编不挂确认；提示词／门禁文案／人设话术同源；**协议不给发挥空间——发挥的每一处，最后都是账上一笔查无此因的红。**

剧本库：声明式步骤对「说这句话 → 话面期望 + 库面期望」，加剧本零改码。收尾：台账只认本轮新增、清待批、快照差集清场。首轮抓住的真缺陷：转告行被转写漂移（钉死原文）；回 1 太快踩驻留下限（睡五秒——机器人先学会像人）；旧「默认值要确认」条款与新协议打架，绕过登记。**剧本库首先是缺陷探针：绿不是产出，抓到的红才是。**

沙子：审计落盘可能晚于响应两秒；驻留边界留半秒容差；每轮换新会话号；断言别截「已拒」（「已被人拒」对不上）。

## 七、收束

```
用户说一句
    → agent 平台（一门牌一面，一 agent 一 skill）
    → MCP 网关（六业务面 + 普查面）
    → 墙（形状／白名单／写确认／预算；读也过前三项；不管转述）
         ├ 读：助手只读 → ERP
         └ 写：一次性凭据（≤10 分钟）+ 驻留下限 → 确认后换执行账号落库
    → ERPNext（创建人＝执行账号；审计＝助手编排链；待批单只作台账＋「已拒」否决）

绿只认审计行和库面，不认话面。
```

### 两本考卷（规模与口径；考什么、绿认什么见 §1）

| 考卷 | 规模 | 口径 |
|---|---|---|
| 普查 | 约 1376 腿（实体 + 方法键） | 硬失败（错码／传输死／漏打／误写）为零；其中 506 腿（约三分之一）账齐话面糊，按账收口 |
| 剧本 | 84 项（另有更小演示／角色矩阵） | 话面＋库面，两轮全绿 |

只覆盖 MCP 主路与枚举键。导入、定时、WebSocket 未逐打。REST 直连不在普查里；§4 的洞是试出来的，权限层补上后另有探针。

**账是唯一的真相。** 话面会编、模型会抖、层会串、平台会静默降级——只有各层账行，能让你在硬失败为零之后还敢说绿。全称：MCP 主路、枚举键上，审计账为绿；约占三分之一的话面糊不在这句里；剧本是另一张卷。

给做同类系统的人另两条：加固方向不是换更好的模型，是把信任从模型里搬出来；断言要断到层——结果码会说谎。

### 墙管不住什么

- **读侧话面**：管得住册外读不出；管不住转述夹带与白名单内被套读。
- **对话体验**：保库，不保话面说对。
- **会话与身份**：单因子防伪造同意，不防通道冒充。
- **上游漂移**：`--check` 锁不住 ERPNext 升级后的库面。
- **共钥**：普查已拆号；通用助手与笼号仍共钥。
- **平台静默降级**：白名单缺失、配置行尾错误等只降级不报错，未修。

墙也不是永恒教条。若某一天，在同一套枚举键上，审计账与库面连续可复现地给出「零编造、零越界」的证据——认的是账，不是话面——确认层就该被拿出来重新评估：该降档、该改形，还是该撤。没有这类证据之前，确认层按现价保留。墙的存在理由是被数据推翻的，不是被习惯保留的。

开头那句「查询到了2个会计科目」还躺在测试记录里。每次有人问「为什么不让模型直连数据库」，就把它翻出来。

在我们手里这个模型上，它不会在缺工具的时候停下来。

你的系统得替它停。
